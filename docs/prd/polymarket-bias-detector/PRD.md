## 1. 背景与目标

### 1.1 背景

Polymarket 等预测市场里，同一个事件下不同选项的**资金与平台内参与度分布**往往和它的**赔率隐含概率**不一致：

- 某个选项被大量买入、平台内参与/持仓集中，可能已经**过热**，形成泡沫风险。
- 某个赔率不低但少人问津的选项，可能被市场**忽略**，存在冷门机会。
- 用户凭直觉难以判断当前赔率是否「合理」，缺少一个量化的偏差视角。

2026 世界杯期间，Polymarket 上有大量赛事相关市场，这种「热度 ≠ 概率」的错配尤为常见，用户需要一个工具快速识别。

### 1.2 目标

提供一个**预测市场偏差分析器**：用户选择或输入一个 Polymarket 事件（含世界杯赛事事件），系统拉取每个选项的赔率、成交量、流动性、热度，计算**偏差评分**，输出「高热度·泡沫风险 / 低热度·冷门机会 / 合理」的判定，并可生成**可分享的偏差结果卡片**。

| 目标 | 衡量口径 |
| --- | --- |
| 量化偏差 | 每个选项都有明确的偏差评分与三分类标签 |
| 识别泡沫 | 泡沫选项在单事件明细首屏可见区带独立视觉标记；且「路由进入 → 明细区可交互」≤ N 秒（N 由技术方案定，测量起点为路由进入、终点为明细区可交互）。 |
| 发现冷门 | 冷门机会选项被单独成榜、易于发现 |
| 支持传播 | 单事件结果或榜单可一键出图分享 |

### 1.3 非目标（本期不做）

- 不做真实登录/账号体系（后端 JWT 脚手架本期不启用，公开访问，无收藏/历史/个性化）。
- 不接任何第三方数据源（社交热度只用 Polymarket 平台内信号，不接 X/Google Trends）。
- 不做下单、交易、钱包连接等任何交易操作，仅做只读分析。
- 不做时间序列/历史走势分析（偏差基于当前快照，不做 K 线、动量回溯）。
- 不做投资建议输出（结果为「市场偏差观察」，非荐仓）。
- 不做市场内容机器翻译：Polymarket 的事件名/选项名按英文源文本原样展示，不自动译成中文（多语言只覆盖本产品自身 UI 文案，见 4.6 / 5.4）。
- 不引入 AI/LLM 生成分析：偏差评分与三分类为**纯规则计算**（口径见 [bias-algorithm.md](./bias-algorithm.md)），保证可复现、可审计；本期不加入 AI 文案解读或情绪分析。

### 1.4 实现前提（仓库现状约束）

- 本需求落在前后端全栈模板上：前端 React 18 + Vite + TS + TanStack Query + Zustand + Radix；后端 FastAPI + SQLAlchemy + Redis。
- **后端负责对接 Polymarket API**，做拉取、字段归一、偏差计算，向前端输出已算好的分析结果。
- Polymarket API 有速率与稳定性约束，后端需做**缓存**（默认结果缓存，见 `data-source.md`）与**降级**（拉取失败/字段缺失时的兜底，见第 5 节）。
- **可测性支撑**：非生产环境可提供故障注入 / Mock 开关，使「拉取失败±缓存命中」「per-option 参与数据缺失退化」「分享出图/Web Share 失败」等降级分支可稳定复现，用于验收（不进入生产数据路径）。
- 分享海报由**前端出图**（DOM 转图片），不依赖服务端渲染；仅需后端提供**图片代理**解决 Polymarket 跨域图片的 canvas 污染，海报出图与分发（Web Share / 下载 / 复制 / intent）均在前端完成。图片代理须做**安全约束**：域名白名单（仅 Polymarket 图片域）、仅 `https`、仅 `image/*` 内容类型、限制响应大小与超时、禁止跨域重定向（防 SSRF / 开放代理），详见 `data-source.md` 第 3 节。

## 2. 目标用户与角色

本期无账号体系，仅单一访客角色。

| 角色 | 描述 | 关注点 |
| --- | --- | --- |
| 访客（Visitor） | 预测市场参与者 / 观察者 | 某事件里哪个选项被高估、哪个被低估、当前赔率是否合理 |

## 3. 核心概念

| 概念 | 说明 |
| --- | --- |
| 事件（Event） | Polymarket 上的一个事件，含一个或多个选项。例：某场世界杯比赛、某个政治事件。 |
| 选项（Option / Outcome） | 事件下的一个可下注结果。例：「A 队获胜」「平局」「B 队获胜」。 |
| 赔率隐含概率 | 由选项当前价格换算的隐含概率（0~1），事件内归一化后 Σ=1。 |
| 热度（Heat） | 交易热度 + 参与/持仓热度（`social`，沿用名，指平台内 per-option 参与度/持仓分布，非社媒信号）的合成分，全部取自 Polymarket。定义见 `bias-algorithm.md`。 |
| 偏差评分（Bias Score） | 选项「热度份额」与「概率份额」的偏离，映射到 -100~+100。正=泡沫、负=冷门、近 0=合理。 |
| 偏差标签 | 由偏差评分分档：高热度·泡沫风险 / 低热度·冷门机会 / 合理。 |

## 4. 功能范围（MVP）

### 4.0 信息架构与导航

- 首页设两个顶层视图（Tab）：**事件列表**（4.1）与**偏差排行**（4.4）。默认进入「事件列表」。
- **进入排行的正向入口**：在顶层「偏差排行」Tab 直接进入，对当前 Tab 的默认事件列表做聚合；从单事件明细也可切换到「偏差排行」视图。
- **单事件明细（4.3）与列表/排行的回跳**：从事件列表卡片或排行榜单项点击进入单事件明细；单事件明细提供面包屑/返回，可回到来源列表；排行榜单项可回跳其所属单事件明细。

### 4.1 默认事件列表

- 首页展示系统默认事件列表，分两个分类 Tab：
  - **Polymarket 热门事件**：按成交量/流动性等取当前热门事件。
  - **世界杯赛事事件**：Polymarket 事件中按体育/足球/World Cup 标签或关键词筛选的子集（同一数据源，仅分类展示）。
- 每个事件以卡片呈现：事件名 + 各选项的赔率 + 偏差标签（列表卡片给出**概览级**结论，明细进入 4.3）。
  - **卡片偏差标签语义**：取事件内 `|bias|` 最大的选项对应的偏差标签作为**事件级概览结论**，并在卡片同时标注该选项名。
- **规模上限**：每个 Tab 默认列表条数上限、是否分页/加载更多由技术方案定（建议默认 20 条一页）；超出上限不在首屏无限堆叠。

### 4.2 事件输入

用户可通过三种方式选定一个事件：

- **A. 从 Polymarket 热门列表选择**。
- **B. 从世界杯赛事列表选择**。
- **C. 手动输入**：粘贴 Polymarket 事件链接（解析 slug）或输入事件名称（走 Polymarket 搜索，返回候选供选择）。
  - **链接解析归属**：前端仅做 URL 形态校验（是否为合法 Polymarket 链接格式）；slug 提取与有效性判定由后端完成并返回结果。
  - **搜索能力**：Polymarket 公开搜索能力待技术方案阶段验证；若不可用，则退化为在已缓存事件集内做本地模糊匹配，并向用户标注「仅在当前收录事件范围内搜索」。
  - 输入无法解析/搜不到时，给出明确的空态与重试引导。

### 4.3 单事件偏差明细

进入某个事件后：

- 列出该事件全部选项，每个选项展示：**赔率（隐含概率）、热度、偏差评分、偏差标签**。
- 支持按偏差评分排序，泡沫风险与冷门机会选项有明显视觉区分。
- 展示**数据完整度**：若事件内任一选项缺少 per-option 参与数据，全事件热度退化为纯交易热度并标注（见 `bias-algorithm.md`）。
- 事件级展示 `commentCount` 等「事件关注度」标签（不参与单选项偏差）。

### 4.4 多事件偏差排行

- 对**当前 Tab 的默认事件列表**内的所有选项做聚合分析，输出三个榜：
  - **高热度·泡沫风险榜**（`bias_i ≥ +T` 的选项，按偏差评分降序）
  - **低热度·冷门机会榜**（`bias_i ≤ -T` 的选项，按偏差评分升序）
  - **合理选项列表**（`|bias_i| < T` 的选项）
  - 三榜取集与三分类阈值 `T` 对齐、互斥无交集（口径见 `bias-algorithm.md` 第 5 节）。
- 每条榜单项标注所属事件、选项、赔率、偏差评分，可点击回到对应单事件明细。
- **规模上限**：每个榜单展示 TopN（N 由技术方案定，建议默认 10），超出部分不展示或折叠；聚合基数为当前 Tab 默认列表内的事件。

### 4.5 分享海报与分发

**海报出图**

- 对**单事件偏差结果**或**某个榜单**，前端将 DOM 渲染为图片，**主选单库 `html-to-image`**；出图失败直接降级为下载/重试，**不追求多库像素对齐兜底**。
- 尺寸：MVP 先提供**移动端竖版**尺寸（移动优先）；**桌面横版列为后续增强**，MVP 桌面可复用竖版。
- 出图口径：海报为**受控离屏（off-screen）子集**渲染——只纳入受控的卡片元素，**内联字体**，避免背景图 / CSS 滤镜 / icon-font 等易致导出空白的元素；按 `devicePixelRatio`（≥2）高清渲染；出图前等待字体就绪（`document.fonts.ready`）；海报内 Polymarket 图片经**后端图片代理**同源加载，避免跨域污染 canvas 导致导出失败。
- 卡片内容：事件/榜单标题、核心选项与偏差标签、偏差评分、**数据快照时间**（Polymarket 数据获取时间）与**海报生成时间**（二者区分展示）、来源标注（Polymarket）；文案跟随当前界面语言（中/英，见 4.6）。

**分发通道（多主流媒体）**

- **移动端 / H5**：调用 Web Share API 分享**图片文件**到系统原生分享面板，用户可直达 X / Telegram / WhatsApp / 微信等已安装应用。
- **桌面端**：提供下载海报、复制链接，以及 X / Telegram / Facebook / Reddit 的 intent 分享（分享文案 + 链接）入口；**复制图片到剪贴板**为**条件能力**——在支持的浏览器（安全上下文 / HTTPS，Chromium 系较完整）可用，否则该入口自动隐藏并回退为下载。
- **降级**：不支持 Web Share API（或不支持分享文件）时退化为下载 + 复制链接；出图失败给出明确错误态与重试，不静默失败。
- 本期**不生成服务端分享页 / OG 富预览卡**（贴链接在社媒时间线上的富预览图为后续增强）。

### 4.6 多语言（i18n）

- 支持 **English + 中文** 两种界面语言，提供语言切换入口，默认 English。
- 本地化范围 = **本产品自身文案**：导航/按钮/空态/错误提示、偏差三分类标签（泡沫风险 / 冷门机会 / 合理）、榜单与分享卡片的措辞、数据完整度与时间标注等。
- **不本地化 = 市场内容**：Polymarket 的事件名、选项名按英文源文本原样展示，不做机器翻译（见非目标 1.3）。
- **文案插值**：凡含市场内容的句子（如「{eventName} 中 {optionName} 偏差最高」）一律用带占位符的插值 key，事件名/选项名作为**不翻译变量**注入，不与译文拼接硬编码。
- 语言选择在会话内保持（如本地存储），刷新后不丢失。

## 5. 业务规则与边界

### 5.1 偏差判定规则

- 偏差评分与三分类的完整口径见 [bias-algorithm.md](./bias-algorithm.md)：热度合成权重（默认交易 0.7 / 社交 0.3）、份额归一、偏差阈值（默认 ±15）均为**可配置**，PRD 只约定语义与默认值。

### 5.2 数据降级规则

| 场景 | 处理 |
| --- | --- |
| 某选项无 per-option 参与数据 | 触发全事件退化为纯交易热度（口径见 `bias-algorithm.md` 3.5），前端标注「纯交易热度」。 |
| 事件仅单一选项或缺少价格 | 无法计算事件内相对偏差，标注「不适用偏差分析」，仅展示原始数据。 |
| 世界杯 Tab 无匹配事件 | 展示明确空态（「当前无世界杯相关事件」）并引导切回热门 Tab，不显示空白列表。 |
| 某榜单无入榜项 | 该榜展示空态（「暂无入榜选项」），其余两榜正常展示，不整页报错。 |
| Polymarket 拉取失败 | 优先返回缓存快照并标注数据时间；无缓存时给出错误态与重试。 |
| 手动输入无法解析/搜不到 | 明确空态 + 重试引导，不静默失败。 |

- **降级判定谓词**：「无 per-option 参与数据」= 该字段缺失或为 `null` 视为无；值为 `0` 视为有效 0（正常参与计算），不触发退化。
- **状态归属**：偏差结果、降级标注与数据快照时间属**服务端状态**（前端经 Query 缓存承载）；语言等界面偏好属**本地状态**（本地存储）。

### 5.3 数据时效

- 分析结果基于拉取时的**快照**，页面与卡片均标注**数据快照时间**（Polymarket 数据获取时间）。分享海报须同时区分展示「数据快照时间」与「海报生成时间」（见 4.5），二者不得混用。后端缓存 TTL 见 `data-source.md`。

### 5.4 语言与本地化

| 项 | 规则 |
| --- | --- |
| 支持语言 | English、中文 两种，用户可切换，默认 English。 |
| 本地化对象 | 本产品自身 UI 文案与偏差标签（含 zh/en 两套标签文案，见 `bias-algorithm.md` 第 4 节）。 |
| 不本地化对象 | Polymarket 市场内容（事件名、选项名）按英文源文本原样展示。 |
| 数字/时间格式 | 随语言做本地化展示（如千分位、日期格式），偏差评分数值口径不变。 |
| 语言持久化 | 用户所选语言在会话内保持（本地存储），刷新不丢失。 |

## 6. 用户路径（核心闭环）

1. 访客进入首页「事件列表」视图 → 看到默认事件列表（热门 / 世界杯 Tab），卡片上已有偏差标签。
2. 选定事件（列表点击 / 世界杯 Tab / 手动输入链接或名称）。
3. 进入单事件明细 → 看到每个选项的赔率、热度、偏差评分与标签，识别泡沫/冷门；可经面包屑/返回回到列表。
4. 切到「偏差排行」视图 → 对**当前 Tab 的默认事件列表**聚合，看泡沫榜 / 冷门榜 / 合理列表，跨事件对比，可回跳单事件明细。
5. 一键生成分享海报 → 移动端原生面板分享图片 / 桌面端下载·（条件）复制图片·intent 分享。

## 7. 验收标准

| 编号 | 验收项 |
| --- | --- |
| AC-1 | 首页默认列表能展示 Polymarket 热门与世界杯两个分类，卡片含选项、赔率、偏差标签；卡片的偏差标签取事件内 `|bias|` 最大选项的标签作为概览结论，并标注该选项名。 |
| AC-2 | 三种事件输入方式（列表选 / 世界杯选 / 手动输入链接或名称）均可定位到一个事件。 |
| AC-3 | 单事件明细对每个可分析选项输出赔率、热度、偏差评分与三分类标签，口径与 `bias-algorithm.md` 一致；算法口径以 `bias-algorithm.md` 第 8 节「验收黄金样例（fixture）」的固定输入→期望 `bias_i`/标签断言，真实 Polymarket 数据仅做冒烟验证。 |
| AC-4 | 多事件排行能输出泡沫榜、冷门榜、合理列表，且可回跳单事件。 |
| AC-5 | 数据降级规则（社交不足、单选项、拉取失败、输入无效）均有明确态，不静默失败。 |
| AC-6 | 单事件结果与榜单均可生成带来源与时间标注的分享海报（含移动端竖版）；移动端可经 Web Share 原生面板分享图片，桌面端可下载图片、复制链接并经 intent 分享到 X/Telegram/Facebook/Reddit；复制图片到剪贴板为条件能力（支持的浏览器可用、否则自动隐藏并回退下载）；出图或分享失败均有明确态。 |
| AC-7 | 全流程只读，无任何交易/下单/钱包连接入口。 |
