## ADDED Requirements

### Requirement: 分层 TTL 缓存

系统 SHALL 将归一化事件/选项数据缓存到 Redis，并采用分层 TTL：元数据/列表 TTL 较长（分钟级），价格/赔率 TTL 较短（秒~十秒级）；各层具体数值经配置读取。来源：PRD §5.3、data-source §4。

#### Scenario: 元数据与价格分层过期

- **WHEN** 缓存一份归一化事件数据
- **THEN** 元数据/列表部分按较长 TTL 过期、价格/赔率部分按较短 TTL 过期，两者独立失效

#### Scenario: 命中缓存直接返回

- **WHEN** 请求的事件数据在 Redis 中未过期
- **THEN** 直接返回缓存快照，不再实时打 Polymarket 双 API

### Requirement: 缓存结果带数据快照时间

系统 SHALL 使每份缓存的事件/选项数据结果携带**数据快照时间**，返回时一律带上该时间供下游标注。来源：PRD §5.3、data-source §4。

#### Scenario: 返回缓存时带快照时间

- **WHEN** 从缓存读取一份事件数据
- **THEN** 返回结果包含该数据的快照时间字段，标识数据获取时刻

### Requirement: 默认列表定时预取

系统 SHALL 由后端定时任务对默认列表（Polymarket 热门 + 世界杯筛选子集）批量预取入缓存，预取频率与单次批量上限经配置读取并受上游限流约束，使用户请求优先命中缓存。来源：PRD §4.1/§5.3、data-source §3/§4。

#### Scenario: 定时预取默认列表入缓存

- **WHEN** 定时任务按配置频率触发
- **THEN** 系统拉取热门与世界杯默认列表并写入 Redis 缓存，单次拉取数量不超过配置的批量上限

#### Scenario: 用户请求命中预取缓存

- **WHEN** 用户请求默认列表且预取缓存有效
- **THEN** 直接由缓存返回，不逐次实时打上游双 API

### Requirement: 拉取失败降级回退

当实时拉取 Polymarket 失败（含退避重试耗尽）时，系统 SHALL 优先回退到已有缓存快照并标注其快照时间；无缓存快照时 MUST 返回明确错误态供前端重试，MUST NOT 静默失败或返回空成功。来源：PRD §5.2/§5.3、data-source §4/§5。

#### Scenario: 拉取失败但有缓存快照

- **WHEN** 上游拉取失败且该事件存在（即使已过期的）缓存快照
- **THEN** 返回缓存快照并标注其数据快照时间，供前端提示数据可能非最新

#### Scenario: 拉取失败且无缓存

- **WHEN** 上游拉取失败且无任何缓存快照
- **THEN** 返回明确错误态（供 analysis-api 转为业务错误响应），不返回空的成功结果
